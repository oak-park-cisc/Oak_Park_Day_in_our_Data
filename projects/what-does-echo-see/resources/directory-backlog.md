## 5. Notes on how the directory was built

- **Scope:** the directory includes every source the [project card](../docs/project-card.md) lists, plus the organizations in the Township's May 2026 Behavioral Health Resource Guide and FY27 CMHB funding summary. It also includes the Township General Assistance pages and the Village Street Outreach Card, which the Village's Resources for the Unhoused page links to.
- **Left out:** the Oak Park-River Forest Community Foundation. It gives grants to nonprofits and doesn't serve residents directly.
- **The ECHO website doesn't name any partner organizations**, so no row claims to be an ECHO partner.
- **How details were gathered:** web pages were read with automated tools on 2026-10-03, and some team-supplied details are marked in `notes`. Before posting anything publicly, someone should spot-check the phone numbers and hours against the source pages.
- **Some services fit more than one category.** Following the trends page's rule in CLAUDE.md, each one gets a row per category (6 services, 7 extra rows), and `notes` says "Also listed under ...". Edit all copies of a service together.

## 6. Ideas for building this out

1. **One record per service.** Repeated rows can drift apart when one copy is edited. A `service_id` column, or one row with a list of categories, would let the page show a service in several panels while the details live in one place, and stop totals counting it twice.
2. **A status column.** Add `status` (`confirmed`, `unconfirmed`, `conflict`, `possibly_stale`) so the dashboard can grey out or flag rows that need checking.
3. **A freshness check.** Add a test that flags rows whose `checked_on` is more than about six months old, and rows that cite a flyer from an earlier fiscal year.
4. **A link checker.** Add a script that requests each `source_url` and each link in `how_to_reach`, and reports broken links. It should run on demand, not in the regular checks, because some sites block automated requests.
5. **Split up the contact field.** Replace the single `how_to_reach` text with separate `phone`, `address`, `website` and `email` columns, so a dashboard can show tap-to-call buttons and links.
6. **"Who to call" cards.** Write a plain-language card for each ECHO category: crisis first, then the main contact, then other options. This is a stretch goal on the project card.
7. **Compare with ECHO's own referral list.** Ask the ECHO team (`echo@oak-park.us`) which providers they actually refer to. Add the missing ones, and mark the ones they never use.
8. **Waitlist and handoff notes.** Interview people who have used or worked in these services about waitlists and which handoffs work, and record what they say in `notes` or a new `handoff_quality` column.
9. **Spanish and accessibility.** Record which providers offer bilingual staff (Sarah's Inn, Housing Forward's Support Center, Thrive's access coordinator) and whether the location is wheelchair accessible.
10. **Link to ECHO workload.** On the dashboard, join on `echo_category` to show each category's `service_by_month` workload next to its resources. Show the workload as counts of services, never referrals or people, and never add the five breakdowns together.
11. **Refresh routine.** Before each Board of Health review, re-check sections 1, 2 and 4 of this file and update the CSV and `checked_on` together.
